# 멀티 페르소나 코드 리뷰

이 스킬이 호출되면 아래 워크플로우를 즉시 실행하고, 결과를 대화창에 바로 보고하세요. (별도의 .md 파일 생성 금지)

---

## STEP 0 — 플랫폼·실행 방식 확인 + 프로젝트 유형 확인

#### STEP 0-A — 플랫폼·실행 방식 확인

`prompts/parallel-setup.md`의 [플랫폼 확인] → [모델 목록 표시] → [실행 방식 선택] 절차를 따른다.

병렬 선택 시 아래 검토 작업 목록을 제시한 뒤 `prompts/parallel-setup.md`의 [모델 확정] 절차를 따른다.

| # | 검토 작업 | 핵심 체크 |
|---|------|----------|
| 1 | Security | 인젝션, 인증 우회, 민감 정보 노출, 권한 검증 누락 |
| 2 | Performance | N+1 쿼리, 불필요한 반복, 메모리 누수, 캐시 미활용 |
| 3 | Maintainability | 과도한 복잡도, 높은 결합도, SRP 위반, 매직 넘버 |
| 4 | Testing | 테스트 누락, 경계값 미검증, 모킹 과다 |

순차 선택 시 아래 리뷰 워크플로우로 직접 진행한다.

#### STEP 0-B — 프로젝트 유형 확인 (C-1 확인 단계)

리뷰 범위를 확정하기 위해 **반드시** 아래를 수행한다.

1. 현재 수행 위치에서 프로젝트 구조를 탐색한다 (git repo 경계, 하위 앱 폴더 후보 스캔).
2. **단일 애플리케이션 프로젝트**인지 **복수 애플리케이션 프로젝트**인지 판정한다.
3. 판정 결과 + 리뷰 대상 애플리케이션(폴더)을 사용자에게 **반드시 재확인**한다.
4. 확인된 범위 밖은 건드리지 않는다.

## 리뷰 워크플로우

1. 특정 파일이나 패키지가 언급 되면 해당 파일 또는 패키지 및 패키지와 연관되거나 하위의 파일들에 대해서 코드리뷰를 진행한다.
2. 특정 파일이나 패키지가 언급되지 않은 경우에는 `git diff`로 변경 파일 및 변경 내용 파악 (unstaged + staged, 커밋 전 전제)
3. 아래 4개 관점을 독립된 보조 에이전트 작업으로 **병렬 실행** — 관점별 지침은 각각
   `prompts/security.md`, `prompts/performance.md`, `prompts/maintainability.md`, `prompts/testing.md`를 사용
4. 각 관점 결과를 심각도별로 분류·중복 제거
5. 보호 자산인 `template.md`를 실제 최종 출력 계약으로 사용하여 대화창에 종합 리포트 출력 (.md 파일 생성 금지)

네 관점 작업의 원문 결과를 그대로 이어 붙이지 않는다. 각 관점 프롬프트가 요구하는 근거를 취합하고,
중복을 제거한 뒤 `template.md`의 섹션·필드·심각도 구조에 맞춘 하나의 보고서로 변환한다.
`template.md`나 네 관점 프롬프트를 삭제·대체하지 않는다.
