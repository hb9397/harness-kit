# 병렬 실행 환경 설정 (parallel-setup)
# 역할: 호스트 능력 확인 → 실행 방식 선택 → 독립 작업 확정

---

## 라우팅 표

| 호출 지점 | 실행할 섹션 순서 |
|----------|----------------|
| 작업 목록이 이미 확정됨 | [플랫폼 확인] → [실행 방식 선택] → [모델 확정] |
| 작업 목록이 뒤에서 확정됨 | [플랫폼 확인] → [실행 방식 선택 — 선호도만 저장] → 목록 확정 후 [모델 확정] |

---

## [플랫폼 확인]

현재 호스트가 독립 작업을 병렬 실행할 수 있는지 **노출된 도구와 능력으로 확인**한다. 호스트를 관찰할 수 있으면 사용자에게 제품명이나 플랫폼을 다시 묻지 않는다.

- 병렬 실행 능력이 없거나 불명확하면 순차 실행으로 전환한다.
- 특정 제품의 명령, 모델명, 에이전트 생성 구문을 하드코딩하거나 추측하지 않는다.
- 작업자에게도 현재 범위, 승인 상태, 안전 규칙, 보호 자산 규칙을 동일하게 전달한다.

---

## [모델 목록 표시]

호스트가 선택 가능한 작업자 또는 모델 목록을 **직접 제공할 때만** 그 확인된 선택지를 사용한다. 별도 선택 기능이 없으면 호스트 기본값 또는 상속값을 사용하며, 모델을 알아내기 위해 임의 CLI 명령을 실행하지 않는다.

---

## [실행 방식 선택]

병렬 여부가 비용·속도·결과에 실질적인 차이를 만들고 기존 선호가 없을 때만 짧게 확인한다.

> "서로 독립적인 작업을 병렬로 실행할까요, 순차로 실행할까요?
> 병렬은 더 빠를 수 있지만 추가 작업자 비용이 들 수 있습니다."

- 의존 관계가 있거나 같은 파일을 동시에 수정하는 작업은 순차 실행한다.
- 병렬 선호를 먼저 받았지만 목록이 아직 없으면 선호만 저장하고, 실제 목록 확정 뒤 다시 검증한다.

---

## [모델 확정]

확정된 병렬 작업 목록과 독립성·파일 소유권을 보여준다. 호스트가 모델 선택을 지원하는 경우에만 확인된 선택지 안에서 전체 공통값 또는 작업별 값을 정한다. 모델 선택이 품질에 중요하지 않으면 호스트 기본값을 사용하고 불필요한 질문을 만들지 않는다.
