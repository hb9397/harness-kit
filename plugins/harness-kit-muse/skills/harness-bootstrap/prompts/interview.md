# 최소 인터뷰 (interview)

코드에서 확정할 수 없는 앱의 대분류, 아키텍처 선택과 배포 환경만 묻는다. 최대 3회다.
답변이 없거나 "모름"이면 아키텍처는 `미정 — 사용자 선택 필요`로 남기고, 배포 환경은
해당 본문을 비워 둔다.

---

## 질문 원칙

1. **한 번에 하나만** 묻는다.
2. **코드에서 답할 수 있는 건 묻지 않는다.** (스택, 엔드포인트, 디렉토리, 환경 변수 등)
3. 개요와 기능 분류를 상세 범위·성공 기준 수준으로 확정하려고 묻지 않는다.
4. 사용자가 답변 제공을 거부하면 즉시 인터뷰 종료.

---

## 질문 1 (필수) — 앱 대분류

```
이 애플리케이션의 종류, 주 사용 환경·사용자, 제공할 기능의 대분류를
2~3줄로 알려주세요. 세부 기능과 완료 조건은 지금 정하지 않아도 됩니다.
```

**사용처**: PROJECT_DESIGN `01 개요`와 `02 구축 대상 기능 분류`.

답변이 모호하면 **한 번만** 반박한다:

> "앱의 대분류를 구분하기 어렵습니다. 어떤 환경의 누가 어떤 종류의 기능을 쓰는
> 애플리케이션인지 한 문장으로만 보완해 주실 수 있을까요?"

두 번째 반박은 하지 않는다. 그대로 받아 `미정 — 설명 불충분` 표기.

---

## 질문 2 (필수) — 아키텍처 패턴 선택

기술 스택과 현재 패키지·파일 구조를 분석한 뒤에만 묻는다. MVC·MVP·MVVM·계층형·
헥사고날 등 이름이 알려진 패턴을 무조건 후보로 만들지 말고, 이 기술 스택에 실제로
맞는 권장안과 대안만 제시한다.

질문 전에 각 후보의 근거와 패키지·파일 구조 예시를 `text` 트리로 보여준다.

> "기술 스택과 현재 구조를 보면 `[권장 패턴]`을 우선 권합니다. 대안은
> `[대안 패턴]`이며, 위 트리는 각 패턴의 패키지·파일 구조 예시입니다.
> 어떤 패턴을 적용할까요? 수정할 구조가 있으면 함께 알려주세요."

**사용처**: PROJECT_DESIGN `04 아키텍처`.

선택 전에는 추천안을 확정 구조로 쓰지 않는다. 사용자가 선택하지 못하면
`미정 — 사용자 선택 필요`로 남긴다.

---

## 질문 3 (조건부) — 배포 환경

로컬 개발, 개발 서버, 운영 환경의 배포 계약이 코드와 문서에서 모두 확정되지 않았을
때만 묻는다.

> "로컬 개발 환경, 개발 서버 환경, 운영 환경을 각각 어떻게 구성할 예정인가요?
> 환경별 서버 형태(클라우드·물리 서버 등), 운영체제, 배포·실행 방식
> (컨테이너·JAR·정적 배포 등)을 알려주세요. 아직 모르면 배포 환경은 비워 두겠습니다."

**사용처**: PROJECT_DESIGN `06 배포 환경`.

사용자가 모른다고 답하면 확인되지 않은 환경의 본문은 비운다. 일부만 확인되면 확인된
환경만 기록한다.

---

## 묻지 않는 것 (묻고 싶어도 참는다)

| 묻지 않을 것 | 이유 |
|-------------|------|
| 기술 스택 선정 이유 | 설계 의도라 사후 알 수 없음 |
| 코딩 컨벤션 세부 | 기존 코드 스타일에서 역추론 |
| 세부 레이어 의존성 규칙 | 상위 아키텍처 선택 뒤 별도 instruction에서 정할 내용 |
| 금지 패턴 목록 | 코드에 없으면 사용자가 만들어줘야 함 — 이 스킬 범위 밖 |
| 향후 로드맵 | 부트스트랩 범위 밖 |

**중요**: 금지 패턴(instruction의 핵심)은 코드에서 역추론하기 어렵다.
이 스킬은 **뼈대만** 만든다. 상세한 금지 목록은 사용자가 이후 `design-doc`·`context-doc`를 재실행하면서 추가해야 한다는 점을 마지막에 안내한다.

---

## 인터뷰 종료 후

인터뷰가 끝나면 사용자에게 알린다:

> "인터뷰 완료. 이제 코드 분석 결과와 답변을 조합해 설계 문서를 작성합니다.
>
> 참고: 코딩 컨벤션·금지 패턴 같은 팀 규칙은 코드에서 자동 추출이 어렵습니다.
> 부트스트랩이 끝난 뒤, 필요하면 `design-doc` → `context-doc`를 다시 실행해
> 팀 규칙을 추가해 주세요."

## 산출물 라우팅 확인

산출물의 **artifact 의미**와 **대상 앱**이 스캔만으로 확정되지 않을 때만, 기존 질문
예산 안에서 그 차이만 확인한다. plugin·agent 이름을 경로 기준으로 삼지 않으며, 이후
portable bundle 설치·갱신은 `harness-setup`에 handoff한다.
