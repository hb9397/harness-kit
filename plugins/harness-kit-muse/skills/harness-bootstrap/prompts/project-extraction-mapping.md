# 코드 인벤토리 → PROJECT_DESIGN 매핑

Step 2 스캔 결과와 Step 3 인터뷰 답변을 `design-doc`의 프로젝트 전체 공개 산출물
계약에 어떻게 전달할지 정의한다.

> 원칙: 코드와 설정에서 관찰한 사실은 관찰로, 사용자가 선택한 내용은 결정으로
> 구분한다. 상위 기능 분류는 상세 문서와 구현을 제한하는 허용 목록이 아니다.
> 최종 `DESIGN.md`에는 현재 기준 사실만 남긴다. 코드 변경 과정, 이전 구조, 제거·이동·
> 이름 변경 내역과 검토했던 대안은 기록하지 않는다.

## 01. 개요

- 프로젝트명과 한 줄 기술 태그는 매니페스트에서 가져온다.
- 앱의 사용자·환경·제공 가치는 인터뷰 답변과 README의 명시적 설명만 사용한다.
- 앱이 무엇을 제공하는지 2~3개 문단의 대분류 수준으로 정리한다.
- 세부 기능과 하위 분류는 개발 과정에서 보완할 수 있다고 명시한다.

## 02. 구축 대상 기능 분류

- 페이지, 라우트, 컨트롤러, 서비스, 배치 작업, 주요 모듈을 상위 책임별로 묶는다.
- 최초 부트스트랩에서는 확인 가능한 대분류까지만 만든다.
- 각 대분류 아래에는 하위 노드를 추가할 수 있는 빈 목록을 둔다.
- 전체 엔드포인트·클래스·함수를 나열하거나 현재 코드에 없다는 이유로 향후 범위를
  제외하지 않는다.

## 03. 기술 스택

- 언어, 런타임, 프레임워크, UI, 데이터 접근, 빌드 도구를 매니페스트의 버전과 함께
  기록한다.
- lock 파일 전체를 읽지 않고 매니페스트와 빌드 설정에서 확인한다.

## 04. 아키텍처

- 현재 디렉토리와 레이어 구조를 관찰 사실로 요약한다.
- 기술 스택과 앱 성격을 근거로 `design-doc`이 비교할 가치가 있는 아키텍처 패턴만
  권장안과 대안으로 제시하도록 자료를 전달한다.
- 각 후보에는 실제 프로젝트 명칭을 사용한 패키지·파일 구조 예시를 붙인다.
- 사용자가 선택한 패턴과 근거를 결정으로 기록한다. 구조 예시는 별도 파일 규칙이
  확정되기 전까지 설명용이다.

## 05. 애플리케이션 특이사항

다른 고정 섹션에 들어가지 않는 앱 고유 사실을 모은다.

- 외부 API·메시지 브로커·SSO·스토리지·상용 제품 연동
- 앱에만 있는 데이터 저장·처리 경계
- 환경 변수로 갈리는 고유 동작
- README·코드 주석에 명시된 운영 제약
- TODO/FIXME 중 현재 상태를 이해하는 데 필요한 사실

일반 개발 조언이나 모든 앱에 적용되는 규칙은 넣지 않는다. 별도 `주의사항` 섹션은
만들지 않는다.

## 06. 배포 환경

- 로컬 개발, 개발 서버, 운영 환경을 구분한다.
- Dockerfile·Compose·배포 workflow·실행 스크립트에서 서버 형태, 운영체제,
  배포·실행 방식을 확인한다.
- 관찰만으로 환경별 계약을 확정할 수 없으면 인터뷰 답변을 사용한다.
- 사용자가 모른다고 답하고 다른 근거도 없으면 제목만 남기고 본문을 비운다.

## 07. VSCode 익스텐션 추천

- 확인된 기술 스택, 설정 파일과 주 파일 형식에 직접 도움이 되는 확장을 5개 이내로
  추천한다.
- 단순 취향 도구나 프로젝트와 관계없는 일반 확장은 제외한다.

## 세부 인벤토리 인계

API·WebSocket 목록, 데이터 모델, 실행 명령, 환경 변수, 디렉토리 세부 트리처럼
PROJECT_DESIGN의 대분류 문서에 넣지 않은 관찰 정보는 버리지 않는다. Step 6에서
`context-doc`에 별도 관찰 기반 입력으로 함께 전달한다.

다음 항목은 앱 context의 고정 목차를 채울 수 있도록 구분해 전달한다.

| 관찰 정보 | 앱 context 대상 |
|---|---|
| profile 설정·활성화 방법·애플리케이션 실행 명령·포트·엔트리포인트 | 4 실행 프로필 및 실행 방식 |
| 인증정보를 제거한 Git remote·현재 branch·refs와 환경별 branch 기준 | 5 Git 원격 저장소 및 브랜치 |
| Kubernetes·컨테이너·JAR·WAR·정적 build 결과와 환경별 실행 대상 | 6 배포 방식 |
| 현재 코드·설정에서 참조하는 환경 변수 키·profile·용도·비밀 여부 | 8 애플리케이션 사용 환경 변수 목록 |
| 실제 instruction 파일과 적용 조건 | 9 AI 구현 지침 |

실행과 배포 인계에는 DB 생성·migration·seed·접속 명령을 포함하지 않는다. DB 관련
환경 변수 자체가 애플리케이션 실행에 필요하면 실제 값 없이 8번 입력으로만 전달한다.

앱 소유권이 불명확하면 canonical 경로를 추측하지 않고 범위 확인 결과를 따른다.
