# Document Refinement Profile

하네스 산출물 `.md`를 다듬을 때 사용하는 보수적 프로필이다.

## 기본 계약

- 원본 파일은 승인 전 수정하지 않는다.
- 먼저 개선안과 변경 사유를 제시한다.
- 사용자가 승인하면 그때 파일 반영을 수행한다.

## 보호 대상

- 제목 계층과 앵커 역할
- 표 구조
- 코드 fence와 인라인 코드
- 명령어, 경로, URL
- 요구사항 ID, API ID, 화면 ID, 커밋 SHA
- 숫자, 날짜, 버전
- 직접 인용
- 의무 수준 표현

### 디자인 시스템 문서에서 추가로 보호할 값

`.ai-docs/design-system/**` 문서를 다룰 때 아래 값은 그대로 둔다.

- hex, RGB, HSL 색상값
- CSS 변수명과 디자인 토큰 이름
- font family와 weight
- spacing, breakpoint 값
- 기술 스택과 컴포넌트 이름

### 모션 명세 문서에서 추가로 보호할 값

`.ai-docs/design-system/**/motion/**` 문서를 다룰 때 아래 값은 그대로 둔다.

- duration, delay 값
- easing curve 이름과 cubic-bezier 계수
- 애니메이션 대상 속성 이름
- trigger와 상태 이름
- reduced-motion 조건
- 성능 budget

이 값들은 기계적 의미를 가진 데이터다. 윤문은 문장을 다듬는 작업이지 데이터를
바꾸는 작업이 아니다. 값이 바뀌면 문서가 설명하던 구현이 달라진다.

## 개선 우선순위

1. 반복되는 종결어미와 접속어 완화
2. 번역투·명사화 표현을 자연스러운 동사 중심 문장으로 조정
3. 지나치게 기계적인 병렬 구조를 문서 목적에 맞게 정리
4. 긴 문장을 나누되 요구사항 조건은 분리하지 않음
5. 주어·목적어가 흐려진 문장을 명확히 함

## 금지 예시

- `필수`를 `권장`으로 낮추기
- `2026-07-29`를 `오늘`로 바꾸기
- `SFR-021` 같은 식별자를 재작성하기
- 표 행·열을 병합하거나 삭제하기
- 코드 fence 내부 문장까지 윤문하기
