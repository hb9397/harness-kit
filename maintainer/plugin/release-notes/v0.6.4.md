# Harness Kit v0.6.4

`0.6.4`는 `harness-setup`이 설치하는 Codex PreToolUse 훅이 Codex CLI 0.154.0에서
`hook returned invalid pre-tool-use JSON output`을 내던 문제를 바로잡는 패치다.

## 변경 사항

- Codex adapter가 내부 routing 판정 객체를 stdout에 출력하지 않는다. allow는 빈 stdout,
  bypass는 `systemMessage`, deny는 `hookEventName=PreToolUse`를 포함한 deny 응답,
  adapter/core 예외와 잘못된 payload도 같은 deny 응답(exit 0)으로 fail-closed한다.
  Codex CLI 0.154.0 Windows 실측에서 exit 2와 stderr는 도구 실행을 막지 못했다.
- Claude adapter도 allow에서 내부 판정 객체를 출력해 Claude Code가 매 허용 쓰기마다
  `Hook JSON output validation failed` 오류를 표시했다. allow는 이제 빈 stdout으로 끝난다.
- Codex matcher를 `apply_patch|Edit|Write|Bash|MCP|.*`에서 `apply_patch|Bash`로 좁혀
  읽기·검색 도구에서 쓰기 guard가 실행되지 않게 했다.
- 공통 core가 `apply_patch`의 `*** Move to:` 대상도 검사하고, Windows PowerShell 5.1에서도
  SHA-256 계산이 동작한다.
- `install-routing.ps1 -Apply`는 다른 hook entry에 `args`/`commandWindows`가 없어도 실패하지
  않고, 기존 관리 entry를 한 번만 교체한다. 이미 `active`인 host는 config hash가 그대로일
  때만 `active`를 유지하며 `-Check`도 hash drift를 `pending-trust`로 보고한다.

## 기존 프로젝트 적용

플러그인 갱신 뒤 `harness-setup` 갱신으로 `.ai-docs/harness/**` bundle을 다시 렌더링하고,
별도 승인 뒤 `install-routing.ps1 -Apply -TargetHost codex -ApproveHostInstall`을 실행한다.
matcher가 바뀌므로 Codex `/hooks`에서 새 정의를 다시 신뢰해야 한다.

## 호환성

Claude hook 설정과 차단 방식(exit 2/stderr)은 유지된다. 기존 0.6.3 archive와 release는 변경하지
않는다.
